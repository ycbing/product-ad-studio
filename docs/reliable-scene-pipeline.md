# 可复用的真实场景制作流程

本次目标是让选片、构图和错误处理可重复，而不是宣称规则检查能够保证审美或商业效果。

## 使用方式

1. 新项目默认选择“真实场景”。上传同款商品的环境、准备、使用动作、细节、结果视频，不要求额外上传封面图。
2. 点击素材上的“标注动作与保护区域”。同一视频可标注多个片段，记录用途、起止时间、实际动作与同一商品/拍摄组。
3. 观看整段后拖框或填写保护区域。框住该镜头必须保留的商品部位和动作活动范围；不要只标当前一帧。绿色框显示竖屏可见范围，橙色框显示保护区域。无法同时容纳时换竖屏或更合适的素材。
4. 保存标注后生成方案。系统依据用途排序，不依据上传顺序；保持同组，不重用同一时间段，不把图片冒充使用动作，不拉长片段凑时长。
5. 自动选择上方、下方或纯画面，避开已标注区域。仍可手工调整，错误裁切、文字遮挡或越出核对时间会阻止创建样片任务。
6. 观看当前引擎与项目版本的样片，确认后导出。选择商品图展示是明确的另一种制作方式；真实场景缺素材时不会自动降级。

标注是可保存的人工核对依据。没有接入视频语义识别，系统不能自行知道标注是否真实、是否覆盖整段运动、某动作是否吸引观众；仍须认真核对素材并观看成片。

## 稳定性约束

- `scene-model.ts`：五种镜头用途、时间段、保护区域、拍摄组与确认结构。
- `scene-planner.ts`：只用已核对且哈希/商品身份匹配的片段；同样输入得到同样选片、时间、构图和文字位置。UUID 不作为语义输入。
- `scene-framing.ts`：根据源宽高、9:16、焦点与缩放计算真实可见区域，供标注、预览、规划及校验共享。
- `scene-quality.ts`：对照核对记录校验用途顺序、同组连续性、起止时间、重复片段、主体裁切、文字遮挡。裁切后原生像素不足720会提示补高清素材。
- API 与 Worker 均执行校验；不能只绕开前端按钮继续导出。素材内容哈希改变时 Worker 在渲染前拒绝处理。
- 修改商品名/品牌、片段标注或项目内容后，旧核对依据或旧样片确认失效。标注更新保留旧分镜供参考，但必须重建有效引用。
- 制作引擎版本加入任务缓存键与产物记录。引擎升级后，旧视频不被误当新结果，旧样片确认不能授权新引擎导出。修改规划、构图、声音或验收语义时须同步更新 `PIPELINE_VERSION`。
- 场景成片要求画幅/时长/音轨基础检查通过，并完成 VVV 与近黑整帧检查。检查失败或检查器不可用时不发布为成功产物。静止段检查并非语义或美学判断。
- 近黑检查按成片帧率读取32×32缩略帧，98%以上像素接近黑且持续至少0.5秒会失败。它不评估曝光意图，不能代替全片检查。

## 验证

运行 `npm test`、`npm run test:frames`、`npm run typecheck`、`npm run build`。

完整本机隔离验收：启动数据库、Web、Worker 后，设置 `REAL_PRODUCTS_ASSET_DIR` 为已有同系列素材文件夹，使用一个未出现过的 `QUALITY_RUN_ID` 执行 `npm run validate:quality`。素材及授权来源沿用 `fixtures/scene-coffee.json`。

该脚本刻意打乱上传顺序，通过 HTTP 保存五类片段，重复生成比较选片，再测试错误裁切、遮挡、越界、过期核对、商品身份变化、缓存去重与旧引擎确认。实际导出低清样片与1080p成片，并在新建的可丢弃副本中注入素材字节改变，确认 Worker 拒绝后立即恢复文件，再软删除该副本。

脚本中的标注确认和导出确认都是隔离测试动作，不表示连续看片、听音或商家验收。不得在真实客户项目上自动执行这些确认。
