# 商品剧情广告工厂：产品设计 v0.1

状态：首版实施基线；商业需求尚待试单验证。日期：2026-10-25。
暂用名：Product Ad Studio（商品广告工作室）。名称与视觉品牌可后续调整。

## 1. 产品目标

帮助小商家把已有商品图、卖点与使用素材，制作成一条可以发布并继续修改的竖屏剧情广告。
核心承诺：上传真实商品资料 → 选择剧情 → 确认分镜 → 观看样片 → 导出视频。
第一版验证目标：商家是否愿意发布成片，以及是否愿意付费再做。
不承诺投放转化率、商品销量或未经验证的固定生成时间。

## 2. 首批用户与场景

首批用户：需要持续制作商品短视频、已有商品图片的小商家和代运营人员。
首个品类假设：厨房与家居收纳用品。通过试单确认；模板架构允许扩展其他品类。
用户具备：至少一张清晰商品图、确认过的卖点，以及需要时的使用实拍。
首版交付：15–25 秒、9:16、1080 × 1920、H.264 MP4，含旁白、字幕与可选音乐。
“剧情”首版定义为生活问题与商品解决过程，支持旁白叙事；复杂人物对白后续再做。

## 3. MVP 边界

必须具备：
- 商品资料录入、图片上传与素材预览。
- 生成或编辑三个剧情开头，选择一个进入制作。
- 五镜头结构化分镜；逐镜头编辑文案、素材、时长和旁白。
- 一套完整生产模板；另外两种开头使用同一后段结构。
- 低清样片、用户确认、1080p 导出。
- 单镜头重新生成与失败重试，复用未变化的素材。
- 项目保存、任务状态、错误提示、视频下载。
- 实际费用记录；真实服务未配置时明确进入演示模式。

首版延后：付款与充值系统、多人团队、复杂人物表演、自动口型、批量投放、自动爆款判断、任意参考视频一键复制、模板市场。
测试版本只供项目所有者与受邀试用者使用；公开多用户部署前必须完成身份与数据隔离。

## 4. 最小成功案例

输入：一张厨房收纳架图片、三个确认卖点、价格（可选）、目标人群“租房上班族”。
输出：三种开头草稿；选择一种后得到五镜头样片，可修改旁白，最后导出成片。
三种开头：痛点叙述、生活提问、场景展示。
模板示例：问题出现 3 秒 → 问题展开 4 秒 → 商品展示 4 秒 → 卖点展示 5 秒 → 行动引导 4 秒。
以上是初始时间预算；以真实语音时长调整，超时应提示用户修改或明确调整时长。

## 5. 用户流程与页面

### 5.1 项目列表
显示封面、商品名、最近编辑时间、状态和最近一次成片。
操作：新建、继续编辑、查看成片、删除。
状态：草稿、生成中、待确认、渲染中、完成、失败。

### 5.2 新建商品广告
必填：商品名、至少一张图片、至少一个确认卖点、目标人群。
可选：使用场景、价格、优惠、品牌 Logo、购买引导、使用实拍、禁用表述。
使用结构化字段并允许用户更正；不自动编造规格、检测报告、优惠和功效。
上传后检查文件实际类型与大小；首版支持 JPEG/PNG/WebP，单张上限 15 MB，总数上限 10 张。

### 5.3 剧情选择
每张方案卡显示开头、故事摘要、预计时长、需要补充的素材。
提供“编辑”和“使用此方案”；重新生成前说明会新增模型调用。
缺少服务密钥时显示演示方案，不伪装为真实模型结果。

### 5.4 分镜工作台
左侧五个分镜，中央画面预览，右侧属性编辑。
每镜包含：视觉描述、原始素材、旁白、屏幕文字、时长、允许生成范围。
原始商品素材具有明确标记；生成背景不能被误认为真实使用演示。
编辑分镜后，已有预览显示“已过期”；不可继续把旧成片显示为当前版本。
提供预览配音、替换素材、重做本镜与生成样片。

### 5.5 样片确认与导出
样片目标 540 × 960，使用同一时间线和字幕布局。
用户确认商品外观、卖点、台词与价格后，允许正式导出。
导出页显示阶段、失败原因和重试入口；完成后提供播放、下载和返回编辑。
正式版本与样片关联输入版本；输入变化后需要再次确认。

## 6. 视频生产策略

商品本体优先用用户上传的原图、透明抠图或真实视频；程序负责排版与运动。
首个可用版本用原图排版、背景色、字幕和配音完成交付，不依赖生成视频。
背景生图是增强能力；需要商品交互的镜头优先索取实拍或换用可表达的版式。
旁白使用一个配置好的 TTS 提供方；适配层支持日后替换，不同时堆叠多个降级链。
字幕按配音分段时长排布；如供应商不返回词级时间戳，明确采用分句字幕。
文字层保留编辑能力，不让图片模型绘制价格、规格和行动引导。
音乐只能使用已确认可用的素材；首版可选择无背景音乐。

## 7. VVV 实际复用方案

VVV 是 Remotion 模板工具链，不是可直接调用的托管视频生成 API。
源码审查完成前，以下均为拟复用项，不声称已经集成：
- Remotion 工程组织、输入规范与模板目录方式。
- Python 工具中适用的媒体探测、渲染检查和证据记录能力。
- 可编辑工程交付与素材许可记录设计。

需要新写：商品广告模板、商品资料模型、网页工作台、剧情规划、任务编排、费用记录和服务适配。
婚礼模板只用于理解工程结构；首版广告使用自制版式，不套用婚礼场景。
初期优先保留独立上游副本并记录 commit；避免把上游代码大规模复制后失去版本来源。
每个实际复用文件记录来源和许可，保留 MIT 声明；字体、配乐等逐项处理。
VVV 的现有检查阈值需要按广告模板重新校准；节拍同步不作为所有广告的强制通过条件。
不把 .vvv 格式作为首版产品前置条件；稳定后评估导入导出兼容性。

## 8. 技术架构

Web：Next.js + TypeScript，负责页面、项目接口和任务查询。
数据库：PostgreSQL，保存结构化数据；生产迁移使用版本化迁移文件。
任务：独立 Node.js worker，通过 PostgreSQL 任务表领取任务，首版不额外要求 Redis。
渲染：独立 Remotion 工程与 Node.js 渲染进程；使用 FFmpeg/FFprobe 和适用的 VVV 检查工具。
存储：本地开发目录 / 生产对象存储适配层；数据库保存对象键，不保存会过期的签名 URL。
供应商：文本、语音、可选图像分别使用接口适配层；密钥仅存在服务端环境变量中。

Web 与渲染进程分离。Remotion/FFmpeg 需要原生可执行程序和足够资源；Cloudflare Workers 不能承担此渲染任务。
因此完整首版优先采用容器或普通服务器部署；如使用 Sites，只承载适用的 Web 部分并连接外部渲染服务。
不为了展示页面而把核心渲染功能替换为假的成功结果。

## 9. 最小数据模型

Product：商品资料、卖点、素材引用、品牌与禁用表述。
Project：商品、画幅、模板版本、当前修订、状态。
Concept：开头、剧情摘要、结构化镜头草稿、生成来源。
Shot：顺序、文案、素材引用、旁白、时长、版本。
Asset：文件键、实际 MIME、尺寸、哈希、来源和使用权限记录。
Job：类型、状态、项目版本、幂等键、尝试次数、心跳与错误。
Artifact：样片/正式成片/配音等产物、对应输入指纹、检查结果。
UsageEvent：供应商调用、请求关联 ID、实际或估算用量、费用状态。
Approval：用户确认的项目修订与时间；编辑后旧确认失效。

## 10. 任务可靠性

阶段：校验 → 剧情 → 素材准备 → 配音 → 时间线 → 样片 → 确认 → 正式渲染 → 检查。
任务状态：queued / running / succeeded / failed / cancelled。
按项目修订与操作类型建立幂等键，避免重复点击触发重复扣费和同版本渲染。
Worker 使用锁、租约和心跳；进程中断后可恢复过期任务。
外部生成请求如结果不明，先查询供应商状态；不盲目再次收费调用。
仅对可重试错误自动重试，设置次数和退避；输入错误直接返回修改建议。
日志不包含密钥；错误展示使用可理解说明和追踪编号。
修改内容按依赖失效：台词影响配音、字幕和视频；价格文字影响相关画面与成片。

## 11. 成本与权限

首版记录实际调用成本和每条被接受成片的总成本，不预先承诺固定利润。
正式收费前完成：报价确认、预算上限、重复请求去重和失败费用处理规则。
生成接口必须校验访问权限和速率；用户只能访问自己的项目与文件。
预签名下载地址按请求生成，并限制有效期；删除项目时安排文件清理。
演示模式和生产模式隔离，页面清楚显示可用能力与未配置服务。

## 12. 验收标准

- 从商品上传到生成一个真实可播放 MP4 的流程可完成。
- 商品原始素材可追溯；价格与卖点没有超出用户确认信息。
- 分镜可编辑；修改后正确标记过期产物并生成对应新版本。
- 样片与正式成片使用相同输入修订；导出前必须有有效确认。
- 视频比例、分辨率、音视频时长与字幕区域通过检查，无意外黑帧和明显截断。
- 同版本重复提交不会产生重复生成任务。
- 失败显示具体阶段，可恢复；无服务配置时不显示虚假生成成功。
- 多用户版本通过项目、素材和下载权限隔离检查后才开放。
- 完成至少一轮人工连续看片与听音；自动检查不能替代内容确认。

## 13. 实施顺序

里程碑 A：确认 VVV 代码与环境，建立项目结构、输入 schema 和一套商品模板。
里程碑 B：用固定合法样例与本地素材完成真实渲染；先打通不依赖模型的制作链。
里程碑 C：接入商品录入、项目保存和分镜编辑；样片与导出可操作。
里程碑 D：接入文本与语音模型、后台任务、成本记录和失败恢复。
里程碑 E：端到端验收，邀请商家试单，按反馈调整模板。
每个里程碑按实际完成情况报告，不把 UI 演示描述为生产功能完成。

## 14. 商业验证

寻找 3–5 位真实商家，每位制作两条广告；统计发布率、修改次数、总成本与重复购买意愿。
先观察创意接受和制作交付，再评估投放结果；不把一次销量变化归因于视频工具。
对比不同开头时，固定后段、商品、时长与引导，减少其他变量。
如果商家反复要求真实使用视频，优先改善素材接入，不继续堆积纯生图能力。
如果主要需求变成代运营批量生产，再扩展批量项目与模板管理。

## 15. 待试用确认的假设

首批品类是否合适；商家是否接受旁白加图文形式；实际配音与渲染成本；需要多少人工修改。
以上不阻塞基础工程；模型供应商与生产部署在接入前根据可用账号和环境确定。
